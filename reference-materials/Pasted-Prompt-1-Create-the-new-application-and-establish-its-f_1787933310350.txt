Prompt 1 - Create the new application and establish its foundation

Create a new Replit application from scratch. Nothing has previously been built in Replit. The supplied HTML prototype was created outside Replit, and the workbooks and screenshots are reference material only. Do not treat them as an existing application, repository, architecture, or interface that must be continued.

Before designing the new application, inspect every supplied reference file. Read the HTML logic, workbook sheets, formulas, lookup lists, and screenshots. Use them to identify business rules, controlled values, examples, contradictions, and gaps. Do not assume the screenshots are the specification, and do not copy the external HTML structure merely because it exists.

We are replacing a product-first UTM generator with a segment-led Campaign Governance application. The application must eventually create, organize, name, govern, budget, and track integrated Sales and Marketing campaigns. Campaigns may involve multiple products, segments, personas, regions, channels, fiscal years, and quarters.

For this phase, build only the foundation. Do not attempt to implement the entire application in one pass.

Requirements:

Create a clean, maintainable Replit project for the new application.

Preserve every supplied external file unchanged in a clearly labeled reference-materials directory. Do not mix these files into production application code.

Create a source-assessment document describing:

What each reference file contains

Which business rules and controlled values may be reusable

Conflicts, gaps, unclear definitions, and risky assumptions

Which inputs are suitable only as examples or incomplete seed data

An explicit statement that no prior Replit application or technical architecture exists

Create an architecture decision document describing the proposed application structure, database approach, security boundaries, testing approach, deployment approach, risks, assumptions, and unresolved integration questions.

Use a supportable greenfield stack. Unless Replit's current supported defaults provide an equivalent maintainable approach, use:

React and TypeScript for the interface

A TypeScript server/API layer

PostgreSQL for persistent data

A migration-based ORM supported in Replit

Do not store authoritative taxonomy values in page components or hardcoded channel-specific arrays. The interface must load governed values from persistent reference tables.

Establish a responsive application shell with these primary areas:

Home

Create Campaign

Campaign Directory

Approvals and QA

Taxonomy Administration

Reporting and Exports

Add a persistent database connection, schema migration process, seed process, environment-variable validation, structured error handling, and health endpoint.

Add basic automated test infrastructure for unit, database, API, and user-interface testing.

Add a project decision log and implementation evidence log. Record material architecture and data decisions rather than silently changing them.

Treat uploaded segment, persona, product, and channel values as incomplete seed data. Label imported values with source, status, and taxonomy version. Do not present them as a complete enterprise list.

Do not implement live Salesforce, advertising, email, or finance integrations in this phase.

Non-negotiable design rules:

One enduring Campaign Key must survive name, fiscal-period, and taxonomy changes.

Products, segments, personas, regions, and channels must be related data, not positional pieces of a long encoded name.

Campaign names must be understandable without a code guide.

A campaign can have many products and many audiences.

Fiscal planning periods must not replace the enduring campaign identity.

Historical taxonomy values must be retired or superseded, never deleted if referenced.

No personally identifiable or confidential information may be placed in URLs, UTMs, logs, or generated identifiers.

Acceptance criteria:

A new Replit application has been created with no dependency on a prior application or repository.

The application starts successfully from a clean install.

The database can be initialized and migrated without manual database edits.

The application shell renders at desktop and tablet widths.

Navigation routes work and show intentional empty states.

A health check confirms the application and database are reachable.

Automated smoke tests pass.

Source-assessment, architecture, decision, and implementation-evidence documents exist.

External reference files remain unchanged in the reference-materials directory.

At completion, provide:

Files changed

Database and architecture decisions

Commands run

Test results

Screenshots of the application shell

Known gaps and assumptions

A clear statement of whether every acceptance criterion passed

Stop after this phase. Do not begin the taxonomy or campaign workflow until instructed.
